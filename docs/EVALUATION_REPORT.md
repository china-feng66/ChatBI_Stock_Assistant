# Agent 指标与评测记录

更新时间：2026-07-19。所有结果均为本地研究测试，不访问完整数据集，不代表策略具有实盘收益。

## 指标口径

### 路由与澄清

- Top-1 准确率：首选意图等于标注意图的案例数 / 可执行标注案例数。
- Top-3 召回率：标注意图出现在前三候选中的案例数 / 可执行标注案例数。
- 澄清 Precision / Recall / F1：衡量低置信度和小间隔请求是否被正确要求澄清。
- Unsupported 阻断召回率：实盘下单、自动交易和收益保证等越界请求被阻断的比例。
- 同时记录每案例 token、p50/p95 延迟和错误类型。

### Agent 运行

- 技术终态率：进入 completed、blocked 或 needs_clarification 的任务数 / 已启动任务数。
- 评测任务成功率：实际终态及全部确定性门禁符合预期的案例数 / 案例数。
- 研究完成率：Risk 批准的研究任务数 / 可执行研究任务数。
- 证据完整率：包含 provider、as_of、adjustment_status、freshness 和 fingerprint 的证据批次数 / 证据批次数。
- 每个 Agent 分别统计调用数、输入/输出/总 token、平均/p95 延迟、错误率和阶段耗时。
- 通信边从持久化 Agent 事件推导，契约固定为 typed_research_state；不保存完整 prompt 或密钥。

### 确定性门禁

- T+1 违规数、Risk 审批、数据复权状态、证据指纹、token 预算和最多一次白名单修复。
- `llm_usage` append-only 账本是调用数和 token 的权威来源，任务终态必须与账本对账。
- LLM-as-Judge 只评相关性、清晰度和证据一致性，不能覆盖数值门禁。

## 真实 Qwen 路由评测

固定标注集共 34 条，模型为 `qwen-plus`，三路权重固定为 `LLM 45% + TF-IDF 30% + 关键词 25%`。

### 缺陷基线

首次真实运行 34/34 返回、0 API 错误、5,900 tokens、p95 约 2.53 秒，但 Top-1 仅 40.0%。根因是 Qwen 返回顶层概率键，适配器只解析嵌套 `probabilities`，多数请求因而回退为 market_query。旧 benchmark 仍保留，未覆盖或删除。

修复 JSON 结构后，第二个基线为 Top-1 76.7%、Top-3 100%、澄清召回 75.0%、越界阻断 66.7%。它暴露了关键词通道过度依赖“策略”，并漏掉手续费、滑点、因子、排序和收益保证等金融语义。

### 校准后结果

benchmark_id：`b2a3bdc0be7747c0ada12e6c9be32f06`

| 指标 | 结果 |
|---|---:|
| 完成案例 / API 错误 | 34 / 0 |
| Top-1 accuracy | 96.7% |
| Top-3 recall | 100.0% |
| 澄清 precision / recall / F1 | 50.0% / 100.0% / 66.7% |
| Unsupported 阻断召回 | 100.0% |
| 总 token / 平均每案例 | 5,939 / 174.7 |

唯一 Top-1 错误是“解释信号确认与执行时间错开的原理”在知识解释与策略分析之间进入澄清，属于保守失败，没有误执行研究工具。校准没有修改标注答案或 45/30/25 权重；改动是扩充高精度金融关键词、移除过宽的“策略”规则、对泛化请求强制澄清，并对实盘和收益保证增加确定性安全阻断。
